# SQL Query Logging Configuration Guide

## Overview
The application is now configured to display all SQL queries generated by Entity Framework Core in the console when running in Development mode.

## What's Been Configured

### 1. appsettings.Development.json
Enhanced logging configuration to capture Entity Framework operations:
- **Database.Command**: Shows SQL queries being executed
- **Query**: Shows LINQ query translation information
- **Update**: Shows database update operations
- **Console output**: Formatted with timestamps for better readability

### 2. ServiceCollectionExtensions.cs
Added development-specific Entity Framework configuration:
- **EnableSensitiveDataLogging()**: Shows actual parameter values in SQL queries
- **EnableDetailedErrors()**: Provides detailed error information
- **LogTo(Console.WriteLine)**: Outputs SQL directly to console

## How to Use

### Running the Application
When you run the application in Development mode:
```bash
dotnet run --environment Development
```

### What You'll See in Console

#### Example Query Output:
```sql
HH:mm:ss info: Microsoft.EntityFrameworkCore.Database.Command[20101]
      Executed DbCommand (23ms) [Parameters=[@__email_0='admin@example.com' (Size = 256)], CommandType='Text', CommandTimeout='30']
      SELECT `a`.`Id`, `a`.`AccessFailedCount`, `a`.`AvatarUrl`, `a`.`ConcurrencyStamp`, `a`.`CreatedAt`, `a`.`Description`, `a`.`Email`, `a`.`EmailConfirmed`, `a`.`FullName`, `a`.`IsActive`, `a`.`IsSuperAdmin`, `a`.`LockoutEnabled`, `a`.`LockoutEnd`, `a`.`NormalizedEmail`, `a`.`NormalizedUserName`, `a`.`PasswordHash`, `a`.`PhoneNumber`, `a`.`PhoneNumberConfirmed`, `a`.`SecurityStamp`, `a`.`TwoFactorEnabled`, `a`.`UpdatedAt`, `a`.`UserName`
      FROM `AspNetUsers` AS `a`
      WHERE `a`.`NormalizedEmail` = @__email_0
      LIMIT 1
```

## Key Features

### 1. Parameter Values
With `EnableSensitiveDataLogging()`, you can see actual parameter values:
- `@__email_0='admin@example.com'` instead of just `@__email_0`

### 2. Execution Time
Each query shows execution time:
- `Executed DbCommand (23ms)`

### 3. Query Type Information
Shows whether it's a SELECT, INSERT, UPDATE, or DELETE operation

### 4. LINQ to SQL Translation
When using LINQ queries like:
```csharp
var users = await _context.Users
    .Where(u => u.IsActive)
    .OrderBy(u => u.FullName)
    .ToListAsync();
```

You'll see the generated SQL:
```sql
SELECT `u`.`Id`, `u`.`FullName`, ...
FROM `Users` AS `u`
WHERE `u`.`IsActive` = TRUE
ORDER BY `u`.`FullName`
```

## Controlling Log Output

### To Disable SQL Logging
In `appsettings.Development.json`, change the log level:
```json
"Microsoft.EntityFrameworkCore.Database.Command": "Warning"
```

### To Show Only Errors
```json
"Microsoft.EntityFrameworkCore.Database.Command": "Error"
```

### Log Levels Available
- **Trace**: Most detailed logs
- **Debug**: Debugging information
- **Information**: General information (current setting)
- **Warning**: Warning messages only
- **Error**: Error messages only
- **Critical**: Critical failures only
- **None**: No logging

## Security Note
⚠️ **IMPORTANT**: This configuration is for DEVELOPMENT ONLY!
- `EnableSensitiveDataLogging()` exposes actual data values
- Never enable this in production environments
- The configuration automatically checks for Development environment

## Benefits for Development

1. **Debug Performance Issues**: See which queries are slow
2. **Verify LINQ Translation**: Ensure LINQ queries generate efficient SQL
3. **Identify N+1 Problems**: Spot when multiple queries are executed unnecessarily
4. **Parameter Inspection**: See actual values being passed to database
5. **Learning Tool**: Understand how Entity Framework translates LINQ to SQL

## Common Scenarios

### Tracking Query Count
Watch the console to see how many queries are executed for a single page load.

### Finding Slow Queries
Look for queries with high execution times (e.g., >100ms).

### Debugging Failed Queries
Detailed error messages will show exactly what went wrong with SQL syntax or constraints.

## Troubleshooting

If you don't see SQL queries in the console:
1. Ensure `ASPNETCORE_ENVIRONMENT` is set to "Development"
2. Check that MySQL connection string is valid
3. Verify logging configuration in appsettings.Development.json
4. Restart the application after configuration changes
